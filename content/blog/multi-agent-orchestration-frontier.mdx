Few architectural ideas demo better on a Friday afternoon: or fail faster under Monday traffic: than multi-agent swarms.

Empirical production data anchors the tradeoff clearly: fanning a complex research or coding problem out across parallel subagents can lift recall significantly on broad search tasks while consuming **3.5x to 15x as many tokens** as a single well-contextualized loop. Worse, UC Berkeley's `MAST` audit of more than 1,600 multi-agent traces (`arXiv:2503.13657`, Cemri et al.) demonstrated that **fourteen recurring failure modes stem from specification, handoff context loss, and missing termination verifiers** rather than raw model IQ.

Before splitting a workflow into five conversing personas, ask whether one state machine with clean context and deterministic tools solves the job first. When parallel subagents genuinely earn their token tax, choose your orchestration layer with clear eyes.

## The production framework landscape

| Stack / Ecosystem | Recommended Default | Core Strength | Watch Out For |
|---|---|---|---|
| **Python · Explicit State Graphs** | **LangGraph 1.x** | Mature checkpointing, pause/resume HITL gates, deepest production footprint | Verbose boilerplate on tiny linear flows |
| **TypeScript / Node** | **Mastra 1.x** | End-to-end TypeScript ergonomics, clean tool/workflow primitives, strong DX | Keep long-running state backed by durable storage |
| **Python · Strict Type Safety** | **Pydantic AI (+ Logfire &amp; Temporal)** | Cleanest typed schemas, dependency injection, model-agnostic | Pair with Temporal when runs exceed 60 seconds |
| **.NET &amp; Enterprise Microsoft** | **Microsoft Agent Framework (`MAF`)** | Unifies AutoGen + Semantic Kernel with first-class C#, Python, MCP &amp; A2A | Migrate off legacy standalone AutoGen |
| **Stateful Long-Horizon Memory** | **Letta** | Explicit core / recall / archival memory blocks ([see Long-Term Memory](/blog/long-term-memory-for-agents)) | Overkill for stateless request-response pipelines |
| **Minimal Sandboxed Code Actions** | **smolagents** | ~1,000-line codebase emitting sandboxed Python actions | Thin out-of-the-box enterprise governance |
| **Durable Substrate (Beneath All)** | **Temporal** | Activity checkpointing cuts wasted retry compute by ~60% across crashes/deploys | Unnecessary for sub-30-second synchronous calls |

## Why durable execution matters more than agent persona prompts

When an orchestration pipeline spans twenty tool calls, external webhook waits, and human approval pauses, process restarts and transient 502s are guaranteed. Teams migrating prototypes into production discover quickly that **durable state checkpointing**: resuming from Activity 14 instead of re-billing Activities 1 through 13: decides both reliability and gross margin.

Whether you use LangGraph's native persistence or wrap Pydantic AI / SDK steps as Temporal Activities, treat durability and idempotency keys as non-negotiable whenever a run crosses sixty seconds.

## Preventing the three `MAST` multi-agent failure clusters

1. **Specification & Role Drift:** Never let two peer agents "debate" in freeform prose over shared mutable state. Pass typed JSON artifacts (`Pydantic` / `Zod`) between an explicit **Orchestrator** and bounded, read-scoped **Subagents**.
2. **Context Pollution Across Handoffs:** Sending full raw tool histories between agents blows past [token budgets](/blog/token-budgeting-for-startups) and degrades attention. Return concise, schema-validated summaries plus source pointers from each subagent.
3. **False Consensus & Missing Verifiers:** Two LLMs agreeing with each other is not verification. Terminate every multi-agent workflow at a deterministic verifier (`tsc`, SQL reconciliation, citation-span check, or [6-layer eval harness](/blog/eval-harness-catches-regressions)) paired with [Level-2 human sign-off](/blog/the-hitl-standard) on external actions.

## Architectural rule of thumb

Start with a **single state-machine harness** + [scoped MCP tools](/blog/mcp-server-audit-2026). Add **parallel read-only subagents** only when independent search or file partitions must be explored simultaneously, and keep all external writes centralized behind one deterministic gate ([see Loop Engineering](/blog/loop-engineering)).
