## Breaking the "Lethal Trifecta" in Connected Agents

Indirect prompt injection happens whenever an agent simultaneously holds **all three** of these capabilities in one turn:
1. **Access to private data** (inbox, CRM, internal docs)
2. **Exposure to untrusted external input** (an inbound vendor PDF, cold email, or scraped webpage containing hidden instructions)
3. **Unapproved external egress or state mutation** (`send_email`, `fetch(arbitrary_url)`, `transfer_funds`, markdown image URL exfiltration)

**Architectural Fix:** Break at least one leg of the triangle structurally in code, never via a polite system prompt saying *"Ignore malicious instructions."* Parse untrusted documents inside an isolated zero-tool extraction call that emits strictly typed enum/numeric/citation fields, and require human Level-2 sign-off before any outbound write or external URL fetch.

## 4-Legged Identity: Resource Owner, Client, Service, and Agent

Traditional OAuth assumes three parties. Agentic systems introduce a fourth actor whose permissions must be **strictly narrower than the human delegator's**:
- Issue short-lived, task-scoped tokens (`gmail.compose` draft creation without `gmail.send`, read-only SQL views restricted to the caller's tenant row, zero destructive DDL).
- Log `actor_human_id` alongside `agent_run_id` on every audit record.
- Pair every loop with hard token/dollar circuit breakers (`max_steps: 12`, `max_cost_usd: 0.75`) so a malformed retry loop fails closed in seconds rather than burning `$800` overnight.
